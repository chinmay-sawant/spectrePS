## Summary

The batch2 stressful-corpus tarball is pinned and fetchable. A new bulk manifest records the archive SHA-512 and all 5,613 member digests, `gen.go` gains `-fetch-bulk` with staged, per-member verification, and `make validation-fetch BULK=1` is the one command that provisions it. A plain `make validation-fetch` prints the 4.5 GB cost and fetches none of it. The README and development docs now name the provisioning command, which neither page did before.

---

## Motivation / context

- Plans: `plans/v0.0.5/8-real-world-corpus.md` phase 3, row 3.10.
- Related: PR #20, the batch2 recovery audit.
- The batch2 corpus is 5,613 files, 6,063,564,131 bytes extracted, and a 4.5 GB download. It lived on one machine, fetched by hand with curl. The PR #20 notes recorded that the audit could not be rerun from a clean checkout, because neither the bytes nor a manifest for them were in the repository.
- Separately, `make test` already ran the fetched validation rows when they were present, but `README.md` and `documentation/development.md` never said how a machine gets them. A user could run `make test` for months and never see the 3,101-row fetched tier.

## Changes

### The bulk manifest

- `sampledata/validation/bulk.tsv` is the archive-level pin. Its single row pins `https://labs.pdfa.org/stressful-corpus/pdfs_202011/batch2.tgz` at SHA-512 `d96c5e20f4e1d86ab69feb5cd5fc0f651e28eb21ff04f4918e0ff09abbadfd842905240345d77c949d31cb307b3567ad4cf307f5c80688ee90287c69adcdb141` and 4,496,841,248 bytes. The digest was confirmed against the upstream `.sha512` sidecar, not only computed locally.
- `sampledata/validation/bulk/batch2.members.tsv` holds 5,613 rows of `sha256`, `bytes`, and `path`, generated by streaming the archive itself, so the digests describe the bytes a fetch receives rather than a prior extraction.

### The fetch path

- `internal/validation/gen.go` gains `-fetch-bulk`. The flow fails closed: download into the content-addressed cache, check the archive SHA-512 and byte count, extract to a staging directory, check every member SHA-256 and byte count, and only then move files into `external/_bulk/`.
- `-verify-only -fetch-bulk` checks the extracted files with no network. A missing or corrupt member is reported by path.
- The bulk download gets its own HTTP client. The row client sets `Client.Timeout` to five minutes, and that timeout covers the body read, so a 4.5 GB download on a slow link would abort every attempt part way. The bulk client bounds only the response header wait.
- Extraction rejects absolute and `..` archive member names, and fails when the archive holds a member the members manifest does not list.

### Make and docs

- `make validation-fetch BULK=1` passes `-fetch-bulk` through, and `make validation-verify BULK=1` verifies the extracted files. `make help` names the size.
- A plain `make validation-fetch` prints:
  `gen: bulk tier not fetched: batch2.tgz, 5613 files, 4.5 GB (4.19 GiB) download; run make validation-fetch BULK=1 to add it`
- `README.md` gains a Test section naming the provisioning commands. `documentation/development.md` lists the eight missing corpus and veraPDF targets and explains the two tiers and the bulk opt-in. `documentation/test.md` records that a fresh clone skips the live tier until the fetch runs once.
- `internal/validation/manifest.go` skips `bulk.tsv` and the `bulk/` member folder in the unlisted-file check, the same way it skips `text/expected`.

## Impact

| Area | Impact |
|------|--------|
| **Performance** | None on `make test` or `make lint`; the bulk tier never runs under either. A warm `make validation-fetch BULK=1` verifies 4.5 GB of archive plus 6.1 GB of tree in about 1.5 minutes. |
| **Memory** | Extraction streams through `io.Copy`; no file is buffered whole. |
| **Behavior / correctness** | `make validation-fetch` is unchanged by default except for the printed notice. `BULK=1` is opt-in. `make test` still never reads the bulk files. |
| **API / CLI** | No exported API change. `gen.go` is a build-ignored script and gains one flag. |
| **Dependencies** | None added. The extractor uses `archive/tar`, `compress/gzip`, and `crypto/sha512` from the standard library. |
| **Binary size / build time** | None; the fetcher is not part of the binary. |
