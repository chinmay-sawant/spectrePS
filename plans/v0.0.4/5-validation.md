## Overview

v0.0.3 is released and `plans/v0.0.3/v0.0.3-closure.md` records `make lint` and `make test` on the merged tree for 2026-09-25. This file proves the same features again, from the user's side, with two instruments. Code-based validation turns every case in `documentation/test.md` into a test that runs under `make test`. The audit behind this file found 15 documented claims with no matching test, several CLI flag and exit-code paths with none, and one package, `internal/engine`, with no test file at all. Physical validation adds a checked-in corpus of real PDF and PostScript files under `sampledata/validation/`, each with a recorded source, license, and SHA-256, and runs the same commands a user runs on them.

The oracle rules do not change. `documentation/test.md:5` is the contract: `CompareRaster` compares RGB pixel bytes, `CompareFiles` compares file bytes, text compares text and geometry, and PNG, JPEG, TIFF, and PDF container bytes are not oracles. A corpus file either paints or fails with a named error. A blank success is a failure.

No phase calls `/usr/bin/gs`, starts another process, or opens a network connection. The corpus fetcher is a build-ignored generator in the shape of `internal/font/gen.go` and `internal/pdfa/gen_ua2_samples.go`: pinned commits, a SHA-256 per file, fail closed, deterministic bytes. Phase 11 runs external proof tools by hand only, outside `make lint` and `make test`, in the shape of `make pdfa-check`. The integrator owns `plans/v0.0.4/00-program.md`, the closure file, and the `plans/v0.0.1/10-deferred.md` moves; this file touches none of them.

## Executive summary

Phase 1 builds the corpus folder, the manifest, and the fetcher. Phase 2 proves the library and CLI contract: two instances, every context path, nil documents, exit codes 0 to 3, and the import boundary. Phase 3 proves the PostScript interpreter and the raster formats. Phase 4 proves PDF opening, page trees, content operators, and the named refusals. Phase 5 proves Flate, DCT, CCITT, and JPEG2000 decode, including the error shapes. Phase 6 proves text, fonts, and extraction against real font-bearing PDFs. Phase 7 proves the measurement and compare functions. Phase 8 proves the writers at levels 0 to 5, the PostScript output, and the bitmap PDFs. Phase 9 proves the PDF/A-4 and PDF/UA-2 preflights. Phase 10 proves the `gs` argv mode. Phase 11 adds the external reference proofs and is the cut line. Phase 12 routes the findings, maps the tests back to `documentation/test.md`, and closes the file.

Every new test is named `TestValidation<Area>` so `go test -count=1 ./... -run TestValidation` runs the suite as one group and `make test` keeps running it with everything else.
